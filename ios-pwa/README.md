# Wallet iOS PWA

状态：1.6.0 为报表周/月/年、趋势截止周期和年度支出画像增加上一/下一周期按钮；保留图表下方详情、分类导出、AI、用户管理和数据隔离。Windows HTTP/HTTPS 服务已部署；iPhone 实际操作需按验收表确认。

工作分支：`codex/ios-development`。

## 目标与范围

在本目录开发适合 iPhone 使用的个人记账 PWA，可添加到主屏幕，并在首次成功加载和缓存后离线使用。

第一版覆盖现有应用的四个页面：首页、记一笔、报表、趋势；支持消费记录增删改查、分类与子分类、月预算、历史筛选、统计图表和数据导入导出。

采用本地数据存储、可切换的本机用户和手动备份。云端账号、自动同步、推送及 App Store 原生安装包暂不纳入范围。

## 技术方案

- 延续现有 Vue 3、ECharts 和静态 HTML/CSS/JavaScript 结构，不需要安装依赖或打包。日期计算使用原生 UTC 日历运算，避免时区和跨年周偏差。
- 优先参考 `desktop/frontend/dist/` 中已经拆分的领域逻辑和图表模块，逐项验证后迁移。
- 为 iPhone 重新设计页面布局、导航、表单和弹层；采用系统字体、统一 SVG 图标、分组列表和移动端触摸尺寸。
- 使用 IndexedDB 保存账目、预算和子分类，设置独立数据库名称、版本和升级流程。
- 使用 Web App Manifest、主屏幕图标和 Service Worker 提供安装、离线缓存及版本更新能力。
- PWA 资源及 Service Worker 的作用范围限定在本应用目录，支持部署到网站子路径。
- 现有网页版和 Windows 桌面版继续独立运行。

## 开发环境与数据迁移

- 当前 Windows 可完成编码、静态资源服务和浏览器调试；Node.js 用于领域逻辑测试，Python 或 Node.js 可提供本地 HTTP 服务。
- 本方案不需要安装 Xcode、Wails 或 Go，也不需要原生应用签名；最终需要 iPhone 验证 Safari 和主屏幕模式的实际行为。
- Service Worker 本地开发可使用 `localhost`；iPhone 访问部署站点时使用 HTTPS，普通局域网 HTTP 地址不足以验证完整离线能力。
- 从现有网页或桌面版导出 CSV，再在 PWA 中导入。不同设备的浏览器数据不会自动共享；旧 CSV 只包含账目，预算及自定义子分类需另行设置或补充迁移方案。
- 浏览器本地存储仍可能被用户清除或被系统回收，因此完整备份是第一版必备功能；持久化存储申请作为辅助措施。

参考：[Service Worker 安全上下文要求](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)、[WebKit 存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)。

## 本地运行

### Windows 局域网部署

在仓库根目录运行 `powershell -ExecutionPolicy Bypass -File ios-pwa/start-windows.ps1`。默认启动 HTTPS 服务（18770）和 HTTP 证书设置入口（18769）。脚本选择已连接的物理网卡，校验并解压当前发布包，只将发布资源作为网站目录，在后台启动 Python 服务并输出手机可打开的地址。可显式指定 `-Address 192.168.1.3 -Port 18769`；地址必须属于当前电脑。已有匹配服务会复用，其他占用端口的进程不会被终止。

手机连接同一局域网后用 Safari 打开输出的证书设置地址，按页面步骤下载、安装并信任 Wallet 证书，再打开 HTTPS 地址。首次启动时若 Windows 防火墙询问 Python 网络访问，请仅允许需要使用的网络。如只需旧的 HTTP 服务，可使用 `-HttpOnly`（须先停止现有服务）；HTTP 不启用 PWA 离线缓存。

停止服务：`powershell -ExecutionPolicy Bypass -File ios-pwa/stop-windows.ps1`。进程信息及日志位于忽略目录 `release/`；服务不会设置开机自启，电脑重启后需再次执行启动脚本。路由器分配的 IP 变化后也需重新启动并使用新地址；若已记账，变更地址前分别导出各用户 JSON 备份。

### 本机 HTTPS 与 iPhone 离线设置

当前配置：应用 `https://192.168.1.3:18770/`；手机设置页面 `http://192.168.1.3:18769/https-setup/`。

1. 若已在 HTTP 旧地址记账，先为每个用户分别导出 JSON 完整备份；HTTPS 是不同浏览器存储来源，不能直接读取 HTTP 的旧账本。
2. iPhone Safari 打开设置页面，点击“下载 Wallet 证书”，允许下载描述文件。到手机“设置”→“已下载描述文件”→“安装”，完成证书安装。
3. “设置”→“通用”→“关于本机”→“证书信任设置”，开启 `Wallet Local HTTPS CA` 的完全信任。[苹果说明](https://support.apple.com/zh-cn/102390)
4. 打开新的 HTTPS 地址，从 Safari“共享”重新“添加到主屏幕”，开启“作为网页 App 打开”。旧图标仍指向 HTTP。
5. 从新图标打开，保持联网，等设置显示“离线资源已就绪”。再开启飞行模式并重新打开，验证新增记录、关闭重开、统计和用户切换。需要迁移旧账目时，在对应用户下导入先前保存的 JSON。

部署用 Python 3 + `cryptography` 生成一张独立本机 CA 和 180 天服务证书（RSA 2048 / SHA-256 / IP SAN / serverAuth EKU）。根证书约束仅允许私有/回环 IP 及 localhost 名称。再次启动复用原 CA，接近到期或 IP 改变时续签服务证书；iPhone 无需重新安装同一 CA。证书设置描述文件只包含一张根证书。

私钥位于 `release/windows-tls/private/`，目录权限限定当前 Windows 用户及 SYSTEM，未进入发布包。网站只返回发布文件清单和公开证书设置文件，禁止目录列表及其他路径。HTTPS 校验使用指定 CA 正常验证主机名，不关闭证书验证。

默认不会修改 Windows 信任库。若要在这台电脑的浏览器中直接验证 HTTPS，可在前台运行 `powershell -ExecutionPolicy Bypass -File ios-pwa/start-windows-https.ps1 -TrustWindows`，手动确认 Windows 的根证书信任提示；这不影响手机安装自己的证书。手机证书信任和真机离线结果仍需在手机上完成。

部署验证：`python ios-pwa/tests/test-windows-https.py`；健康检查：`python ios-pwa/windows-https.py check`。健康检查验证完整 TLS 链、当前 IP、现代 TLS 协议、应用响应及 iPhone 描述文件 MIME/内容。

在仓库根目录运行：

```powershell
python -m http.server 8080 --bind 127.0.0.1 --directory ios-pwa
```

浏览器打开 `http://127.0.0.1:8080/`。不要通过双击 HTML 验证离线能力。首次访问需联网加载站点；设置面板显示“离线资源已就绪”后，可断网重新打开。

也可以从仓库根目录整体启动静态服务，再访问 `/ios-pwa/`，所有资源路径和 Service Worker 作用域都支持子目录。

数据库名称包含应用路径；域名、端口、路径变化会形成独立账本。迁移访问地址之前先导出完整备份，再到新地址恢复。

## 使用说明

- 用户：点击右上角用户名，或在设置中点击“当前用户”，切换用户或创建独立用户。点击用户右侧铅笔可修改名称；同一编辑面板可删除该用户。
- 概览：本月、今日、本周及本年支出，月预算进度和最近账目。
- 记一笔：输入金额、分类、可选子分类、日期和备注；支持保存后继续记账。点击已有记录可编辑或删除，删除提示保留 10 秒撤销入口。
- 全部账目：搜索、分类和子分类筛选，分批显示；“全选筛选结果”选择整个筛选集合，删除前会显示笔数。
- 报表：周/月/年/全部、历史时间段、饼图/堆叠柱状图、分类下钻及上期对比。图表提示框内可上下滑动查看全部分类；时间较多时拖动图表下方滑动条查看其他月份/年份，滑动条两端可调整显示范围。
- 趋势：近 8 周、12 月、5 年；可展开文字数据，年度分类占比可切换年份。
- 设置：预算、子分类、完整备份、CSV 导入导出、安装说明及更新。界面自动跟随系统浅色/深色外观。

### 用户与数据隔离（1.1.0）

- 账目增删改、删除撤销、月预算、自定义子分类、统计和导入恢复点均独立属于当前用户。不同用户可以有相同的账目 ID，不会相互覆盖。
- 初次升级自动将原来的账目、预算、子分类和恢复点归入 `user1`；`user2` 为空白账本。迁移在同一个 IndexedDB 升级事务中完成，失败会回滚；损坏的原始数据也会保留，不会被空账本替换。
- 新增用户名限 1–24 个字符，忽略首尾空格，不允许仅大小写不同的重名。用户名和内部固定 ID 分离。
- 每个窗口独立选择用户，刷新后保留当前选择，新窗口默认第一位现存用户（初始为 `user1`）。其他窗口修改同一用户时会刷新其账本；若当前用户被删除，自动切换到剩余用户。
- 切换前若有未保存的记账内容，会询问是否放弃；切换成功后清空输入、编辑状态、历史筛选、批量选择、导入预览及删除撤销入口。应用更新草稿按用户保存，异步文件读取和恢复操作不会写入切换后的用户。
- 这些是本机账本身份，不提供密码登录或加密访问控制；拿到当前设备和浏览器的人仍可切换查看各用户。每个用户需要分别导出备份，用户列表不会随单用户备份导出。

### 用户管理与图表滚动（1.2.0）

- 修改名称保留用户固定 ID、账目、预算、子分类和恢复点；名称仍限 1–24 个字符且不可重名，后续导出文件使用新名称。
- 删除前显示目标用户和账目笔数，需再次确认。该用户的账目、预算、子分类、导入恢复点及更新草稿一并清除，无法撤销；建议先切换到该用户导出 JSON。其他用户的数据保留。
- 至少保留一个用户，最后一个用户的删除按钮不可用，存储事务也拒绝删除。删除当前用户后自动切换到剩余用户；其他窗口正在使用被删除用户时也会切换，旧窗口不能重新写回已删除账本。
- 用户列表和图表分类提示框支持纵向滚动；时间轴超过当前屏幕容量时显示滑动条。桌面移动尺寸检查通过，Safari 的手指滑动仍需真机确认。

### AI 分类（1.3.0）

- “记一笔”新增 AI 大分类，默认子分类为“订阅、API 用量、其他”。可在分类管理中添加 ChatGPT 等自定义子分类，保存、筛选、报表下钻、趋势和 CSV/JSON 导入导出均支持 AI。
- 读取旧七类账本、恢复点或 JSON v1/v2 备份时补上缺失的 AI 子分类；原账目、预算、修订号及已有自定义分类保留。明确保存的空 AI 列表和自定义 AI 列表不会被默认值覆盖。
- AI 账目和子分类仍按用户独立保存；原先记在其他分类的订阅不会自动改类，可逐条编辑为 AI。根目录网页版和 Windows 桌面版仍只有原来的七类，暂不支持包含 AI 的导入文件。

### 导出范围与文件名（1.4.0）

- 设置 → “导出账目 CSV”：默认导出当前用户的全部分类，也可选择一个或多个大分类。预览显示笔数、总金额及文件名，未选分类时不能导出；选中没有记录的分类可生成只有表头的 CSV。
- 导出包含全部日期及所选大分类的全部子分类，不受历史页面的搜索、日期或分类筛选影响。多选分类名按应用顺序以 `+` 连接；选择全部八类时文件名使用“全部”。
- 文件名为 `用户名_分类_YYYYMMDD_HHmmss.csv`，例如 `用车_交通+AI_20261002_113045.csv`。时间取实际点击导出的设备本地时间；用户名中的文件路径禁用字符会替换为 `_`。
- JSON 完整备份及分享完整备份继续包含当前用户的所有账目、预算和子分类，统一命名为 `用户名_全部_YYYYMMDD_HHmmss.json`。按分类导出只用于 CSV，不会生成可误覆盖账本的部分 JSON 备份。

### 图表选中与详情（1.5.0）

- 柱图轻点柱条或其所在绘图区，蓝色边框、日期标记和原色柱条指示当前选择，其他柱条淡化。明细放在绘图区及时间滑动条下方，连线和箭头与选中柱的横向位置对应。
- 明细宽度按日期、分类名和金额适配，在图表边缘自动收进卡片；长名称换行，金额保留独立列。超过五行时可在明细内上下滑动；左右箭头可选择当前可见范围的相邻时间，包括零支出月份。
- 趋势图采用同样的下方明细与日期范围，高亮对应数据点。切换用户、分类、周期或图表类型会清除旧选择；移动时间滑动条时，移出可见范围的选择也会清除。
- 饼图保留短小的单分类提示和点击下钻。柱图点击用于选择时间；查看大分类的子分类时，点击图表下方“分类明细”列表。

### 周期快捷切换（1.6.0）

- 报表的周、月、年日期后均有左右按钮，按日历连续切换相邻周期；跨年和 ISO 第 53 周正确衔接。无记录周期也可查看，日期选择框会保留当前周期；切换日期保留大分类下钻与饼/柱图类型。
- 趋势页增加“截至”周期选择和左右按钮：每次向前/后移动一周、一月或一年，保持 8 周、12 月或 5 年窗口长度。当前时间窗口随日期更新，手动选中的历史窗口保持固定；切换周期类型或用户时重置到当前日期。
- 年度支出画像的年份后增加上一年/下一年按钮，独立于上方趋势和报表时间。“全部”报表没有相邻周期，不显示日期箭头；可用日期边界的按钮会禁用。
- 所有控件支持键盘操作，窄屏时图表类型控件及年度年份组可换行，避免挤压日期和左右按钮。

### 数据文件

CSV 列序与现有版本兼容：`id,amount,category,subcategory,date,note,createdAt,updatedAt`，支持 UTF-8 BOM、引号和备注换行。金额必须为正数，最多两位小数；日期必须是 1900–2199 年的有效日期；主分类为餐饮、交通、购物、居住、娱乐、医疗、AI、其他，未知主分类作为无效行显示，不会静默改变分类。

导入 CSV 会显示新增、重复、冲突和无效记录。同 ID 且内容不同默认保留本机记录，只有明确勾选才覆盖文件中更新时间更晚的版本。同一 CSV 内重复 ID 保留首次有效记录并统计重复数。导入的有效子分类会自动补入设置。

CSV 和 JSON 导出只包含当前用户，文件名包含用户名、分类范围和精确到秒的时间；JSON v2 完整备份还包含来源用户标识、版本标识、账目、预算及子分类。兼容旧版 JSON v1 备份和原有 CSV 列格式。

导入预览明确显示目标用户，JSON 还显示来源用户。文件不会自动创建或切换用户：即使备份来自其他用户，确认后也只合并 CSV 或替换当前所选用户的账本。需要给另一位用户恢复时，先切换再导入。每次 CSV 导入或完整恢复前，IndexedDB 都保留该用户自己的一个恢复点，可在设置中恢复；不会读取或覆盖其他用户的恢复点。这个恢复点也存于当前设备，不代替外部备份。

金额内部保存为整数分；所有保存操作使用 IndexedDB 事务，提交完成后才刷新界面。并发窗口修改会从最新事务快照合并，编辑已有记录时检查内容冲突。

## 发布与更新

在仓库根目录运行 `python ios-pwa/package-release.py` 可生成 `ios-pwa/release/wallet-ios-pwa-1.6.0-1.zip` 和 SHA-256 校验文件。脚本先运行领域、离线资源、用户管理、图表和模板测试，再按离线资源清单打包；包内附逐文件校验清单及依赖许可。测试目录、脚本、截图和账目备份不会进入发布包。同版本内容不同会拒绝覆盖，发布修改时应递增缓存版本。

将以下文件原样部署到支持 HTTPS 的静态站点，可部署在根目录或 `/wallet/` 等子路径：

```text
index.html
manifest.webmanifest
sw.js
css/
js/
icons/（运行时仅需要 SVG 和 PNG）
```

无需发布 `tests/`、图标生成脚本或本地备份。无需后端、账号、Xcode 或原生签名。站点必须返回正确的 JS/CSS/JSON MIME 类型，并允许同源访问 `sw.js`；建议 `sw.js` 和 HTML 使用 `Cache-Control: no-cache`。

资源使用同版本整套缓存。每次发布应用资源修改，递增 `sw.js` 中的 `VERSION` 并完整上传全部资源。新资源下载完成后出现更新入口，由用户选择生效。当前输入会先暂存于当前会话，重载后恢复；不要在未递增版本的情况下只替换单个缓存文件。

Windows 启动脚本会在发布版本变化时重新启动其管理的服务，并保留原 IP/端口及证书。已经使用 HTTP 的用户可在同一 Wi-Fi 下重新加载原地址，设置底部应显示 Wallet 1.6.0；导出与图表功能可在原地址使用，但 HTTP 仍无法保证离线关闭重开。HTTPS 用户在设置中检查更新并点击“更新到新版本”。不要清除浏览器网站数据或更换访问地址来更新，原账本保存在对应地址的本机存储中；需要迁移到 HTTPS 时先分别导出各用户 JSON 备份。

iPhone 上：Safari 打开 HTTPS 地址 → 分享菜单 → 添加到主屏幕；若出现“作为网页 App 打开”开关，保持开启。首次缓存完成后可离线使用。真实 iPhone 的安装、软键盘、文件分享和后台恢复仍需要真机确认。

具体操作及结果记录见 [iPhone 真机验收表](RELEASE_CHECKLIST.md)。

node --test ios-pwa/tests/test-domain.js ios-pwa/tests/test-shell.js ios-pwa/tests/test-users.js ios-pwa/tests/test-charts.js

模板文件使用 Vue 语法。如需格式化 HTML，应使用 Vue parser，并在格式化后运行 `test-template.js`；不要让普通 HTML 格式化器拆开插值中的字符串。
